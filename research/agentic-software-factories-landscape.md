# Agents write the code; engineers build the factory

As of October 2026, an "agentic software factory" is an operating model, not a product. Work enters as events (tickets, Slack threads, alerts, issue labels). Specialized AI agents carry it through planning, coding in isolated sandboxes, automated verification and AI review. Humans own the intent, the specs, the acceptance scenarios and the "harness" around the agents, and in nearly every production deployment they still make the final merge decision. The model is real and spreading. Stripe merges **more than 1,000 agent-authored PRs a week** ([Stripe](https://stripe.dev/blog/minions-stripes-one-shot-end-to-end-coding-agents)), Vercel's factory produced **25–35% of merged PRs** on its AI SDK within four weeks ([Igor Ostrovsky](https://igoro.com/archive/software-factories/)), and Gartner sized the enterprise coding-agent market at **$9.8–11.0B annualized** in April 2026 ([Virtualization Review](https://virtualizationreview.com/articles/2026/06/05/ai-firms-push-cloud-giants-from-leaders-quadrant-in-gartner-ai-coding-report.aspx)). Engineers assemble factories from four layers. The first is a coding-agent "worker": paid Claude Code, Codex, Cursor, Devin or Factory Droids, or open-source OpenCode, Codex CLI, OpenHands or goose. The second is an orchestration or control plane, such as GitHub Agent HQ, OpenAI Symphony, Agent Orchestrator or a LangGraph/Agent SDK build. The third is sandboxes and tool access (devboxes, E2B, Firecracker, MCP servers). The fourth is verification: AI review such as Bugbot, CodeRabbit or Anthropic's Code Review, plus tests and human gates. The biggest adopters (Stripe, Uber, Shopify, Block) built in-house platforms on top of these parts rather than buying a factory off the shelf. The central lesson of 2026 is that factories move the bottleneck from writing code to verifying it. Teams with weak tests and platforms get more instability, not more speed.

## A factory is defined by its gates, not its agents

The term reuses a manufacturing metaphor that goes back to **1968**, when R. W. Bemer proposed a GE "software factory" and M. D. McIlroy argued for mass-produced components at the NATO Garmisch conference. Hitachi, Microsoft (the 2004 *Software Factories* book) and the US DoD's DevSecOps "software factories" later reused it, but every one of those industrialized the work *around* human-written code ([Augment Code](https://www.augmentcode.com/guides/what-is-a-software-factory)). The 2026 version moves the automation upstream into authoring itself. Augment's definition is the clearest mainstream one: "an agentic software-delivery operating model in which AI agents write, test, and ship code inside a pipeline, while humans control specifications and merge approvals." It explicitly excludes a lone agent in an IDE, because "a factory implies **stages, gates, and records**" ([Augment Code](https://www.augmentcode.com/guides/what-is-a-software-factory)). Igor Ostrovsky's hierarchy is a useful shorthand: **coding agent → cloud agent → factory**, where a factory starts work from events and coordinates agents through structured workflows, with people approving key decisions ([Igor Ostrovsky](https://igoro.com/archive/software-factories/)).

Three definitions compete, and they differ mainly on how much human review survives. The **governed enterprise pipeline** (Augment, BCG Platinion, TrueFoundry) keeps humans at the spec and merge gates. BCG Platinion declared in March 2026 that "the Agentic Software Factory era" had begun, and it argues that quality depends on harness architecture and how precisely intent is specified ([BCG Platinion](https://www.bcgplatinion.com/insights/the-agentic-software-factory)). The **dark factory** removes human code review entirely. StrongDM's three-person AI team, founded in July 2025, runs on the rules that code "must not be written by humans" and "must not be reviewed by humans." Its tongue-in-cheek benchmark is that a team spending under **$1,000 per engineer per day on tokens** has room to improve ([Simon Willison](https://simonwillison.net/2026/Feb/7/software-factory/)). Dan Shapiro's five-level ladder, modeled on driving automation, puts this at **Level 5** ("lights out"). Level 3 is the human as full-time reviewer and Level 4 is the human as a manager of agents working from specs ([Simon Willison on Shapiro](https://simonwillison.net/2026/Jan/28/the-five-levels/)). A third, smaller usage is "software that builds software" for non-programmers: orchestrator agents that tailor template apps from plain-text needs ([Marmelab](https://marmelab.com/blog/2026/05/22/software-factories-the-future-of-programming.html)). Most enterprise vendors and analysts place themselves at Shapiro L3–L4 and treat L5 as an outlier experiment.

The factory is also distinct from vibe coding, even though both skip line-by-line human review. Vibe coding accepts agent output with little scrutiny. A factory replaces human reading with heavy automated verification, which makes verification the central engineering investment. Karpathy moved his own vocabulary from "vibe coding" to **"agentic engineering"** in 2026, and he called December 2025 the inflection point for agentic coding ([Taskade](https://www.taskade.com/blog/what-is-agentic-engineering); [Josh Thompson](https://joshthompson.co.uk/ai/agentic-engineering-vs-vibe-coding-lessons-karpathy-playbook/)). Simon Willison likewise ties the broad shift to November 2025, when Claude Opus 4.5 and GPT‑5.2 arrived ([Simon Willison](https://simonwillison.net/2026/Feb/7/software-factory/)). The discipline of building factories now has a name, **"harness engineering"**, used by both OpenAI and Thoughtworks.

### The canonical pipeline has five stages and a harness

Published factories converge on the same shape. Augment's five-stage model is **intake → specification → parallel build → verification → ship**, with verification called "the binding constraint" ([Augment Code](https://www.augmentcode.com/guides/what-is-a-software-factory)). Around the pipeline sits the harness. Thoughtworks Technology Radar Vol. 34 (April 2026) splits it into feedforward controls (Agent Skills, spec-driven development, AGENTS.md/CLAUDE.md rule files) and feedback controls (compilers, linters, mutation testing, review), so agents self-correct before a human looks ([Radar Vol. 34 digest](https://agentic-ai.readthedocs.io/en/latest/AgenticTechStack/thoughtworks-radar-vol34/)). The more rigorous designs add **holdout acceptance scenarios** that the coding agents cannot see, to stop them from "teaching to the test." StrongDM scores results with a probabilistic "satisfaction" metric over such scenarios and tests against agent-built "Digital Twin" clones of Okta, Jira, Slack and Google Workspace ([Simon Willison](https://simonwillison.net/2026/Feb/7/software-factory/)), and BCG likewise keeps scenario tests outside the agents' accessible codebase ([BCG Platinion](https://www.bcgplatinion.com/insights/the-agentic-software-factory)).

| Stage | What happens | Typical software in 2026 |
|---|---|---|
| Intake | Tickets, Slack threads, alerts, webhooks, issue labels become agent tasks | Linear/Jira/GitHub issues, Slack bots, OpenAI Symphony, GitHub Copilot coding agent, Google Jules, Tembo |
| Spec / plan | Planning separated from execution, with human approval for larger work | GitHub Spec Kit, OpenSpec, BMAD-METHOD, Kiro, Tessl, agent plan modes |
| Build | Parallel agents in isolated sandboxes or devboxes | Claude Code, Codex, Cursor, Devin, Factory Droids, OpenCode, OpenHands, goose; E2B, Firecracker, Modal, kubernetes-sigs/agent-sandbox |
| Verify | Lint/tests interleaved with agent steps, capped CI-fix loops, AI review | Cursor Bugbot, Graphite, CodeRabbit, Qodo, Copilot code review, Anthropic Code Review |
| Ship | Human merge gate, merge queue, feature flags, canary and rollback | GitHub merge queues, LaunchDarkly guarded releases |

Sources for the table: [Augment Code](https://www.augmentcode.com/guides/what-is-a-software-factory), [Igor Ostrovsky](https://igoro.com/archive/software-factories/), and the tool-specific links in later sections.

## Stripe, Uber and Vercel run factories, but humans still press merge

The best evidence of what factories look like comes from engineering blogs, and nearly every one keeps a human merge gate. **Stripe's "Minions"** are the reference architecture. The agent loop is a fork of Block's open-source goose, with deterministic git, lint and test steps interleaved. Each agent runs in a pre-warmed, internet-isolated devbox that spins up in about 10 seconds; Stripe says git worktrees "wouldn't scale." Tools come from a central MCP server ("Toolshed") with **400+ tools**, of which each agent gets a curated subset. Lint runs in under 5 seconds, tests are selected from a suite of 3M+, and CI is capped at **two rounds** because extra rounds give diminishing returns. Most runs start from a Slack thread and end in a PR a human reviews. Stripe's summary lesson: "engineer attention is the scarce resource" ([Stripe](https://stripe.dev/blog/minions-stripes-one-shot-end-to-end-coding-agents)).

Smaller and open-source factories show the same pattern at lower cost. The Cloudflare/Astro triage bot is a **label-driven state machine on GitHub Actions** (needs triage → reproduce → diagnose → fix → reporter confirms), with agent instructions stored as repo Skills. It cut open issues from **more than 200 to about 30** ([Igor Ostrovsky](https://igoro.com/archive/software-factories/); [triagebot-action](https://github.com/withastro/triagebot-action)). Vercel's AI SDK factory routes GitHub webhooks to specialized agents (classify, fix, feature, docs, review, backport) in sandboxes, with a queue dashboard, and humans review and merge every change. Uber's August 2026 "company-scale factory" runs managed agents for CI repair, review, bug investigation, on-call triage and maintenance, and a growing share of sessions now start from workflows rather than people ([Igor Ostrovsky](https://igoro.com/archive/software-factories/)). Augment's own factory, a vendor self-report, assigns named agent roles (Project Builder, PR Author, Risk Analyzer, Deep Reviewer, Verifier, Incident Investigator) and reports **4.5x size-adjusted output per developer** and median time-to-merge falling from **11.2h to 3.1h**. Augment itself cautions that this was not a controlled study ([Augment](https://www.augmentcode.com/blog/beyond-ai-coding-agents-how-we-built-augments-software-factory)).

| Organization | Factory | Reported scale | Human gate |
|---|---|---|---|
| Stripe | Minions (goose fork, devboxes, MCP Toolshed) | 1,000+ merged PRs/week with no human-written code ([Stripe](https://stripe.dev/blog/minions-stripes-one-shot-end-to-end-coding-agents)) | Human reviews every PR |
| Block | Builderbot | ~1,500 merged PRs/week, ~15% of production changes ([compiled corpus](https://github.com/Chipagosfinest/software-factory)) | Not specified |
| Shopify | River | 1 in 8 merged PRs agent-coauthored ([compiled corpus](https://github.com/Chipagosfinest/software-factory)) | Not specified |
| Uber | Minion + managed-agent factory | 11% of PRs opened by agents ([compiled corpus](https://github.com/Chipagosfinest/software-factory)) | Workflow-dependent |
| Vercel | ai-sdk-factory | 25–35% of merged PRs after 4 weeks ([Ostrovsky](https://igoro.com/archive/software-factories/)) | Human merges every change |
| Microsoft dotnet/runtime | Copilot coding agent | 878 agent PRs, 535 merged (~68%) over ten months ([.NET blog](https://devblogs.microsoft.com/dotnet/ten-months-with-cca-in-dotnet-runtime/)) | Human review |
| OpenAI (internal) | "Harness engineering" with Codex | ~1M lines, ~3.5 PRs/engineer/day, zero manual code ([Latent Space](https://latent.space/p/harness-eng)) | Reportedly none pre-merge (disputed) |

Two patterns stand out. First, **autonomy is granted by task class, not by team**. Triage, maintenance, migrations, backports and CI repair run with few human touchpoints. Spotify, for example, admits only standardized, verifiable task classes into its pipeline ([compiled corpus](https://github.com/Chipagosfinest/software-factory)). Feature work keeps plan approval and a merge gate. Second, the high-volume adopters built on their *existing* developer infrastructure (devboxes, CI, internal MCP servers). The leverage comes from that platform maturity, not from any single vendor tool. OpenAI's internal experiment is the flagship near-dark-factory case, but even there the engineers' job moved to designing environments and feedback loops, and early progress stalled because environments were underspecified ([The Neuron](https://www.theneuron.ai/explainer-articles/openais-harness-engineering-playbook-how-to-ship-1m-lines-of-code-without-writing-any/)). Note that several figures in the table come from a GitHub compilation of company posts rather than the primary blogs. Uber's 11% (PRs opened) and Google's reported 75% (code generated, per secondary coverage of Cloud Next 2026) also measure different things and should not be compared ([8bittoast](https://8bittoast.com/google-code-written-by-ai/)).

## Four model-centric vendors lead a $10B paid market that now bills by the token

On the paid side, Gartner's first **Magic Quadrant for Enterprise AI Coding Agents** (May 20, 2026) named **Anthropic, Cursor, GitHub and OpenAI as Leaders**. AWS and Google fell to Challengers, Cognition dropped from Leader to Challenger, and Tabnine was the lone Visionary. Gartner's mandatory capabilities read like a factory spec: autonomous execution, self-correction, MCP support, human review of agent changes, and action logs with auditability ([Virtualization Review](https://virtualizationreview.com/articles/2026/06/05/ai-firms-push-cloud-giants-from-leaders-quadrant-in-gartner-ai-coding-report.aspx)). Developer usage matches. The Stack Overflow 2026 survey (30,000+ respondents, published Oct 6) found **66% of AI users use coding agents**. Claude Code is used by 66% of AI users and GitHub Copilot by 59%, but only **20%** use AI for deploy, operate or production troubleshooting ([Stack Overflow](https://stackoverflow.blog/2026/10/06/the-results-of-the-2026-developer-survey-are-here/)).

The commercial stack has split into four layers. **Agent harnesses** are the workers. Claude Code passed a **$2.5B run-rate** by February 2026, and SemiAnalysis estimated it authored 4% of public GitHub commits ([Anthropic](https://www.anthropic.com/news/anthropic-raises-30-billion-series-g-funding-380-billion-post-money-valuation)). OpenAI's Codex spans cloud agent, CLI and IDE, with deployments at Cisco, Datadog, Dell and NVIDIA ([OpenAI](https://openai.com/index/gartner-2026-agentic-coding-leader/)). Cursor reached a **$3B annual sales rate** in May 2026 ([Bloomberg](https://www.bloomberg.com/news/articles/2026-05-21/cursor-hits-3-billion-annual-sales-rate-ahead-of-spacex-deal)) and was acquired by **SpaceX for about $60B** on Aug 14 ([Bloomberg Law](https://news.bloomberglaw.com/mergers-and-acquisitions/spacex-completes-its-60-billion-cursor-acquisition)). Cognition (Devin plus Windsurf) was reportedly valued at **$48B** in September with about $900M ARR ([ecmsource](https://ecmsource.com/cognition-48b-series-e-2b-devin-900m-arr-september-2026/), secondary). Factory.ai's Droids reached a **$5B valuation** ([TechFundingNews](https://techfundingnews.com/factory-jumps-to-5b-in-5-months-with-200m-for-its-ai-droids/)). AWS is steering users from Amazon Q Developer to the spec-driven Kiro, and Google's Jules and Antigravity round out the hyperscaler offerings ([TechRepublic](https://www.techrepublic.com/article/news-google-jules-ai-coding-agent/); [cloudzero](https://www.cloudzero.com/blog/google-antigravity-pricing/)).

**Control planes and fleet runtimes** coordinate the workers. GitHub Agent HQ, announced at Universe in October 2025, orchestrates Claude, Codex and Copilot agents from one place ([baeseokjae guide](https://baeseokjae.github.io/posts/github-agent-hq-guide-2026/), secondary). Cursor 2.0 runs parallel agents on worktrees or remote machines, alongside Cloud Agents ([Cursor](https://cursor.com/blog/2-0)). Augment Cosmos coordinates specialized SDLC agents ([Augment](https://www.augmentcode.com/tools/open-source-ai-code-review-tools-worth-trying)). Tembo triggers third-party agents (Claude Code, Codex, OpenCode, Amp) from events rather than prompts ([Tembo](https://www.tembo.io/blog/ai-coding-agents-revolutionizing-development)). Anthropic's Claude Managed Agents, reportedly launched in April 2026, hosts long-lived sandboxed agents for tokens plus about $0.08 per runtime-hour ([aimagicx](https://www.aimagicx.com/blog/claude-managed-agents-cloud-deployment-guide-2026), secondary). The explicit "software factory" branding is strongest at Factory.ai, whose Factory 2.0 extends Droids to review, security, QA and incident response ([yusmpgroup](https://yusmpgroup.com/news/factory-ai-software-factories)), and at Tessl, which calls itself "the platform for building software factories" and sells a spec, skills and context registry ([tessl.io](https://tessl.io/)). **Verification** has become a paid category of its own: Cursor's Bugbot and Graphite (bought in December 2025), CodeRabbit, Qodo's multi-agent reviewers, and Copilot code review ([TechCrunch](https://techcrunch.com/2025/12/19/cursor-continues-acquisition-spree-with-graphite-deal/); [dev.to](https://dev.to/rahulxsingh/qodo-vs-coderabbit-ai-code-review-tools-compared-2026-kdp)). Anthropic's Code Review uses parallel bug-hunting agents and costs **$15–25 per review**, and it deliberately does not approve PRs ("that's still a human call") ([Claude blog](https://www.claude.com/blog/code-review)).

Pricing changed in a way that matters for anyone running agent fleets. List prices still cluster around $20/month for individuals and $20–60 per seat for teams, but in the first half of 2026 nearly every vendor layered **token or credit metering** on top of seats. OpenAI moved Codex to credits on Apr 2 ([morphllm](https://www.morphllm.com/codex-pricing), secondary), and GitHub replaced premium requests with $0.01 "AI Credits" on Jun 1 ([future-stack-reviews](https://future-stack-reviews.com/github-copilot-pricing/), secondary). Kiro bills $20–200 credit tiers with overage at $0.04 per credit ([aitoolpick](https://aitoolpick.org/blog/kiro-pricing-2026/)). Heavy autonomous use broke flat per-seat economics, which is why Gartner expects **AI coding cost per developer to exceed the average developer salary by 2028** ([Virtualization Review](https://virtualizationreview.com/articles/2026/06/05/ai-firms-push-cloud-giants-from-leaders-quadrant-in-gartner-ai-coding-report.aspx)).

## Verification, not generation, caps what a factory can deliver

Every serious source converges on one constraint: generating code is now cheap, and confidence is expensive. Microsoft's ten-month dotnet/runtime review found **~68% of agent PRs merged** ([.NET blog](https://devblogs.microsoft.com/dotnet/ten-months-with-cca-in-dotnet-runtime/)). A secondary analysis of the same data put human PRs at about 87% and fully autonomous agent PRs at about 55%, with a revert rate of only 0.6% ([Start Debugging](https://startdebugging.net/2026/03/copilot-coding-agent-dotnet-runtime-ten-months-data/)). Faros AI telemetry across 10,000+ developers found high-AI teams merged **98% more PRs** but saw **PR review time rise 91%** and PR size rise 154%, with no significant company-level improvement ([Augment Code](https://www.augmentcode.com/guides/what-is-a-software-factory)). DORA 2025 calls AI "an amplifier": throughput rises, but adoption remains associated with **worse delivery stability**, and the gains reach organizational performance only when platform quality is high ([Google Research](https://research.google/pubs/dora-2025-state-of-ai-assisted-software-development-report/); [RedMonk](https://redmonk.com/rstephens/2025/12/18/dora2025/)). McKinsey's September 2026 outlook, via press coverage, reports coding activity up **180%** while shipped releases rose only **30%** ([NewKerala](https://www.newkerala.com/news/a/mckinsey-report-shows-productivity-decline-30-companies-using-382.htm)).

Controlled evidence is far weaker than company self-reports. METR's 2025 RCT found experienced open-source developers **19% slower** with AI while believing they were 20% faster ([Augment Code](https://www.augmentcode.com/guides/what-is-a-software-factory)). Its 2026 follow-up estimated a roughly 18% speedup for returning developers, but METR itself calls this very weak evidence because of selection effects ([particula.tech](https://particula.tech/blog/metr-reversed-19-percent-slower-ai-coding-study), secondary). That sits an order of magnitude below the 3–5x that BCG attributes to factory adopters, which is a practitioner estimate, not a benchmark ([BCG Platinion](https://www.bcgplatinion.com/insights/the-agentic-software-factory)). No independent, peer-reviewed study of a full factory exists yet. Analysts are correspondingly cautious. Gartner places agentic AI at the **Peak of Inflated Expectations** and says fully autonomous agents are not ready for most enterprise uses ([Gartner](https://www.gartner.com/en/articles/hype-cycle-for-agentic-ai)). Thoughtworks puts Claude Code and Cursor in **Adopt** but puts coding agent swarms, codebase cognitive debt and "coding throughput as a measure of productivity" in **Caution** ([Radar Vol. 34 digest](https://agentic-ai.readthedocs.io/en/latest/AgenticTechStack/thoughtworks-radar-vol34/)).

The remaining risks are operational. **Cost**: StrongDM's $1,000 per engineer per day works out to roughly $20k a month per engineer, which Willison frames as a business-model question ([Simon Willison](https://simonwillison.net/2026/Feb/7/software-factory/)). **Security**: Thoughtworks flags "permission-hungry agents" and unreviewed third-party Skills and MCP servers as a supply-chain risk ([Radar Vol. 34 digest](https://agentic-ai.readthedocs.io/en/latest/AgenticTechStack/thoughtworks-radar-vol34/)). **Brittleness**: Gas Town reportedly burned thousands of dollars a month in API costs ([Maggie Appleton](https://maggieappleton.com/gastown)), and a model point release reportedly made its agents "keep wanting to fiddle with Gas Town itself" ([vanja.io](https://vanja.io/yegge-agent-city-four-claims/), secondary). **Ecosystem pushback**: Gentoo, NetBSD and QEMU decline AI-derived code, while LLVM and Kubernetes accept it only with disclosure and a human who can defend it ([policy tracker](https://github.com/melissawm/open-source-ai-contribution-policies)). The working mitigations are consistent across adopters: deterministic steps interleaved with agent steps, capped retry loops, risk-tiered auto-approval, independent reviewer agents, hidden acceptance scenarios, feature-flagged releases, and a human merge on anything that isn't a narrow, verifiable task class.

## Conclusion

The term "software factory" now describes a change in where engineering effort goes, not just a tool category. The scarce skill in 2026 is designing harnesses: specs precise enough to execute, sandboxes cheap enough to run in parallel, and verification strong enough to trust output nobody read line by line. That is why the most productive factories belong to companies that already had excellent CI, devboxes and test suites. It is also why DORA's "amplifier" finding is the most useful predictor of whether a factory will help a given team. The practical entry point is narrow. Start with one verifiable, high-volume task class, such as issue triage, CI repair, dependency bumps or migrations, wired from a ticket or label through a CLI agent in a sandbox to a reviewed PR. That can be built with Claude Code Action or Codex Action and an existing CI in days, not quarters.

The market structure points the same way. Agent harnesses are commoditizing: open-source CLIs ship weekly, and a third-party scaffold has beaten OpenAI's own Codex on Terminal-Bench using the same model ([agentmarketcap.ai](https://agentmarketcap.ai/blog/2026/04/16/terminal-bench-cli-leaderboard-scaffolds-beat-frontier-models)). Meanwhile, value is moving to the layers that make agent output trustworthy and governable: orchestration over interchangeable workers, AI review, holdout-scenario evaluation, and spend controls. Expect the next year's competition to center on verification and cost-per-merged-PR rather than on which agent writes code fastest. Treat any "dark factory" claim for production feature work with skepticism until someone publishes defect-escape and incident data, not just PR counts.
